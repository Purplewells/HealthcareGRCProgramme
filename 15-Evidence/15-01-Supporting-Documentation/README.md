# Supporting Documentation

This folder holds two kinds of artefact, and deliberately keeps them apart:

**Templates** — blank, reusable instruments that document a *process*, not an event. These are safe to produce because they don't claim anything happened; they define how something should be captured when it does.

| Document | Purpose |
|---|---|
| [001-supplier_security_assurance_questionnaire_template](001-supplier_security_assurance_questionnaire_template.md) | The instrument for the Trust-wide supplier assurance process recommended in [043-third_party_risks](../../04-Risk-Management/043-third_party_risks.md) REC-001 and [141-cyber_security_roadmap](../../14-RoadMap/141-cyber_security_roadmap.md) INIT-02 |
| [002-csgg_meeting_minutes_template](002-csgg_meeting_minutes_template.md) | Standard minute structure for the CSGG's recurring agenda set out in [052-roles_and_responsibilities](../../05-Governance/052-roles_and_responsibilities.md) §3 |

**Completed records** — a filled-in questionnaire, actual meeting minutes, a training completion export — are evidence that a specific real-world event occurred. None are included here: this is a fictional case study, and fabricating a record of an event that didn't happen is a different kind of artefact from a template or a narrative assessment document (see [../15-03-Screenshots/README.md](../15-03-Screenshots/README.md) for the same distinction applied to screenshots). This programme's detailed register data already lives in the `.xlsx` files under each phase (e.g. [022-master_assets_register.xlsx](../../02-Asset-Management/022-master_assets_register.xlsx), [113-capa_tracker.xlsx](../../11-Audit/113-capa_tracker.xlsx)), which serve as this programme's evidence base. If this programme is adapted for a real engagement, completed records should be added here named `<source-document-id>_<short-description>.<ext>` and referenced from the document they support.
